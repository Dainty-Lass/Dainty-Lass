# Security and optimization audit, 2026-11-04

Covers dainty-lass at `a53c0d6d` (the Rust workspace and `ui/`) and, for dependencies and the issue classes
below, dainty-restricted on `plan`. Nothing here was played against the 1.14.7 client: the fixes are
covered by the test suites only.

## Method

- `cargo deny check` in both repositories; `bun audit` in `ui/` and restricted's `launcher/`; `npm audit` in
  the Paradox Node reference packages.
- `cargo clippy` with the performance lints the workspace does not turn on (`redundant_clone`,
  `format_collect`, `format_push_string`, `or_fun_call`, `assigning_clones`, `large_stack_arrays` and others).
- A read of every trust boundary for: custom TLS verifiers, secret comparisons, unbounded body reads,
  per-address state that can grow without bound, dynamic SQL, path joins on request input, forwarded-address
  trust and secrets reaching logs.

## Findings fixed

| # | Severity | Where | Finding | Fix |
| --- | --- | --- | --- | --- |
| 1 | Medium | `ui/apps/web/src/lib/auth/session.ts`, `lib/fleet/agent-http.ts` | `clientIp` took the first `X-Forwarded-For` entry, which the client writes. The agent pairing limiter (10 wrong codes per address per 15 minutes) keys on it, so a client sending a new address each time had no limit, and every address added an entry to a map that was never pruned. | `clientIp` takes the last hop, the one the proxy in front appended. Pairing also has an overall limit of 200 failures per window, and the map drops expired windows and is capped at 10,000 addresses. `tests/pairing-limit.test.ts`. |
| 2 | Low | `crates/hostkit/src/invite.rs` (`served_fingerprint`) | `invite` checks the live gateway's certificate against `gateway.crt` with this probe. Its verifier accepted any handshake signature, and a failed handshake still returned the captured leaf, so anything holding the port could replay the gateway's public certificate and pass. | Handshake signatures are checked with the provider's algorithms, and a failed handshake returns `None`. A test runs a real handshake. |
| 3 | Low | `crates/remote/src/transport.rs` | With `REFORGED_REMOTE_WIRE_LOG` set, the enrollment request went to the file whole, one-time token included, and the file took the umask. | The logged copy carries `[redacted]` in place of the token, and the file is created `0600` on Unix. |
| 4 | Low | `crates/gateway/src/feed.rs` | The allowlist helper's reply was buffered whole, with no size limit. The helper is trusted and on loopback, but every other client in the workspace bounds its replies. | Drained through `Limited` at 64 KiB. |
| 5 | Moderate (dependency) | `ui/` | `fflate` 0.7.3 (GHSA-px8p-9vwx-vf98, through `@vercel/og` > `satori`), pinned exactly by `satori`. | `overrides: { "fflate": "0.7.5" }`, a patch release. |
| 6 | Critical / high (dependency) | restricted: `ParadoxBackend`, `ParadoxDirector` | `proxy-addr`, `body-parser`, `qs`, `fast-copy` and `ip-address` advisories. These are the reference packages, not what a server runs since RU9. | `npm audit fix` within range. Both suites pass. |

## Findings left open

- **`esbuild` 0.18.20** (GHSA-67mh-4wv8-2f99) in `ui/`, through `drizzle-kit` > `@esbuild-kit/core-utils`,
  which pins `~0.18.20`. The advisory concerns esbuild's dev server, which drizzle-kit never starts, and it
  is a dev dependency. It goes away when drizzle-kit drops esbuild-kit.
- **`nodemailer`** in `ParadoxBackend`: the fix is a major version (`npm audit fix --force`), so it is left
  for whoever next changes the reference backend.
- **Pairing is locked for everyone** for up to 15 minutes after 200 wrong codes from any mix of addresses.
  A person can lock pairing that way, but cannot guess a code. Pairing is a rare, staff-started step, and
  the lock shows as `rate_limited`.
- **`rifts-transport`'s backend client accepts any certificate** when the admission backend URL is
  `127.0.0.1` or `localhost`. It is loopback only and the capability is still required; noted, not changed.
- `deny.toml` still ignores RUSTSEC-2024-0370 (gtk-rs through Tauri), which no longer matches anything here
  since the launcher moved to dainty-restricted. Left for the CI owner (RR3).

## Checked and sound

Admin key, allowlist secret and ingest key comparisons are constant time (hashed first). Every pin verifier
other than finding 2 checks handshake signatures. Body reads are bounded and timed out (admin, chat
moderation, Epic CDN, the history bucket, content). Chat's per-address SASL and wait maps are pruned.
Content's key cache is capped at 2,000 entries. The dynamic SQL in `rifts-*` builds only from constant
identifiers, with values bound. Branding images are served only by a name the scan listed. Remote enrollment
refuses plain `http://` except on loopback. dainty-restricted's launcher pin verifier checks signatures, and
its log redacts registered keys.

## Optimization

- Hex encoding with `format!("{b:02x}")` per byte, collected into a `String`, made one heap allocation per
  byte. It ran on every admin key check, change-log hash, relay frame id and guard UUID, in 14 places across
  `admin`, `chat`, `epic`, `history-ship`, `hostkit`, `network`, `rifts-relay`, `rifts-transport` and `store`.
  They now use `char::from_digit` on each nibble: the same output with no per-byte allocation.
- `cargo clippy --fix` applied the redundant-clone, `or_fun_call`, `implicit_clone` and `assigning_clones`
  fixes in `hostkit`, `launcher-kit`, `rifts-guard` and `rifts-realms`.
- Not changed, since none of it is hot: `format!` appended to a `String` in setup-time writers (`hosttoml`,
  `nft`, `tls`), two 64 KiB stack buffers in `sha256_file` (duplicated in `doctor.rs` and `selfupdate.rs`,
  which could share one), and the `or_fun_call` hits in `hostconfig.rs` that clippy would not fix on its own.
