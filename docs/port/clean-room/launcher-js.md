## 5. Ambiguities and the assumptions taken

1. **Where the restricted checkout is.** The default is `dainty-restricted` beside the repository root, as ui's script
   has it. From this worktree that is `R:\source\dauntless\.wt\dainty-restricted`, which doesn't exist, so the
   verification set `DAINTY_RESTRICTED_DIR`. In the maintainer's layout (`R:\source\dauntless\dainty-lass`) the
   default finds it. An empty `DAINTY_RESTRICTED_DIR` counts as unset (`||`), where ui's script uses `??`.
2. **ui's Tauri imports.** §1.3 says Bun resolves the UI's extensionless imports itself, which holds for the relative
   ones, but `api.ts` also imports `@tauri-apps/api/*`, and `ui/node_modules` is not installed by anything this package
   runs. Bun's runtime `onResolve` didn't apply to those imports, so `api.test.ts` registers an `onLoad` plugin that
   rewrites the bridge sources' `@tauri-apps/api/<module>` specifiers to this package's copy (the same copy the mocks
   come from), and imports `api.ts` through a computed path (a literal one is resolved before the plugin runs). For
   `tsc`, `tsconfig.json` maps `@tauri-apps/api/*` to `./node_modules/@tauri-apps/api/*` through `paths`.
3. **The timeout case.** `call.ts` arms its deadline with the global `setTimeout`, so the test swaps in one that turns
   any delay of `CALL_TIMEOUT_MS` or more into 5 ms, then restores it. The IPC mock puts every call through the hook
   and returns the hook's pending promise for a dropped one, as Tauri would. Expected results follow `api.ts`: `act`
   resolves to `{ ok: false, error: { code: "unknown" } }`, `copyText` to `false`, and `call` (`setSettings`) rejects
   with `no answer`.
4. **What the IPC mock feeds the hook.** The recorded arguments go through `JSON.parse(JSON.stringify(...))` first,
   as Tauri serialises them: `undefined` fields vanish and a `Channel` becomes `__CHANNEL__:<id>`.
5. **Events in `api.test.ts`.** Tauri's `shouldMockEvents` handles `plugin:event|listen` without calling the mock, so
   the test doesn't use it: the mock records each listen's handler id and the test fires `runCallback` itself. That
   way the listen calls are also checked by the hook.
6. **`settingsPatch` numbers** must be finite (§2.3.7 says only "a number"; JSON can't carry the others anyway).
7. **`index.html` and the SPDX line.** §1.2 has every file *start* with the SPDX comment, §2.1 lists `<!doctype html>`
   first. The comment comes first: a comment before the doctype doesn't put an HTML5 page in quirks mode.
8. **Licence lines in `package.json` and `bun.lock`.** JSON takes no comments and `bun.lock` is generated, so neither
   has an SPDX line; `package.json` says `"license": "MIT"`. `tsconfig.json` (JSONC) has one.
9. **`sign-windows.ts` without a password.** An empty `WINDOWS_CERTIFICATE_PASSWORD` leaves `/p` out rather than
   passing an empty one. `SIGNTOOL` naming a missing file counts as "not found".
10. **`release-config.ts` arguments.** An unknown option or a second positional argument prints the usage and exits 2
    (the spec gives no rule). A pubkey of only whitespace counts as empty.
11. **`dashboard-page.ts`** also refuses a third argument (usage, exit 2). The missing-app message names the
    `package.json` path it looked for.
12. **`hook.js` checks for `index`** also refuse non-numbers and ±Infinity; `number` with neither `min` nor `max`
    accepts any finite number (the shape Tauri's `handler` and `eventId` use). A malformed table entry, or anything
    that throws while checking, drops the call.
13. **NSIS arguments.** `/D=` has to stay unquoted, so `e2e/lib/nsis.ts` passes the command line verbatim
    (`windowsVerbatimArguments`, with the installer path quoted as `argv0`). The version comes from
    `tauri.conf.json`'s `version` when it is a version string, else from `Cargo.toml`'s `[package]`.
14. **The e2e profile.** `REFORGED_DEV_PROFILE` is the `profile-client` / `profile-server` folder, whose `User Data`
    holds the app's data, so the manager's workspace is `profile-server/User Data/Server` (§4.4 step 1).
15. **Fields the e2e scripts read**, taken from the generated types: `host_server_get` → `state`,
    `invite.{link,for}`; `server_config_get` → `config.{configured,name}`; `server_doctor` → `report.checks`;
    `server_invite_list` → `invites[].code`; `admin_action` → `result.player.banned`; `history_query` →
    `page.entries`; `remote_status` → `status.{role,revision,installs[].{node,state,revoked,appliedRevision}}`;
    `remote_invite` → `invite.uri`; the snapshot's `status.{online,name}` and `lastError.code`. After `register` and
    `refresh_status` the scripts poll `get_snapshot` (up to 20 s) rather than reading it once. Buttons are found by
    role and name (`Run doctor`, `Refresh invites`, `Look up`); "scroll the managed-installs panel into view" is
    `#rem-inv-node`'s `scrollIntoViewIfNeeded`.
16. **`App.close()`** disconnects Playwright (`browser.close()`) and then kills the process if it is still running.
    `launch` also takes an optional `viewport` for §4.4's 1280×920.
