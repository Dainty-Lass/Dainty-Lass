Written by the Claude session that ran the conversion until now, for the model that takes it over. A Claude session

## 0. Orientation

DaintyLass is the Reforged Revival launcher and server stack, being ported from Node to one Rust codebase and split
into several repositories. `docs/dainty-lass-plan.md` (in this repository) is the plan; its rows (DS, DF, DU, RU, RF,
RV, RZ, DN, DE, DH, DX, DL) are the unit of work. `MIGRATION_PLAN.md` is the older plan the DaintyLass plan amends.
`AGENTS.md` is the project's rulebook and is binding. This file adds the current state and the lessons learned.

**State in one paragraph.** About 95 branches have been written and merged into the `plan` branch of five repositories,
followed by the 2026-10-28 review-fix branches (`F1`–`F7`). All five `plan` branches build and pass their test suites on
both SQLite and Postgres (`REFORGED_TEST_POSTGRES_URL`). Nothing has been merged into `main` anywhere, nothing has been
played against a real game client, no Forgejo runner has run any workflow, and every hands-on row (canary, cutovers,
real Epic sign-in, real installs) is still the maintainer's. What remains is: rows done in part where a `module-api` or
hunt-session seam is still needed (section 5), known defects (section 7), and the maintainer's decisions and hands-on
rows (section 8). Section 13 records the exact branches, tip SHAs, merge SHAs, and test counts where this session left
off.

## 1. Rules that are easy to get wrong

These come from `AGENTS.md`, the plan and what went wrong during the session. Break none of them.

1. **No AI attribution, ever.** No `Co-Authored-By` trailer, no "Generated with ..." line, no `Claude-Session:` link, in
   a commit or in a PR description. Your tools may add one by default; turn that off or strip it before committing.
   Check every commit you push: `git log --format=%B origin/plan..HEAD | grep -iE 'co-authored|generated with'` must
   print nothing. The maintainer rewrote history once because of this.
2. **One row, one branch.** Branch names are `{type}/{slug}` (`feat/`, `fix/`, `update/`, `docs/`, `ci/`, `deps/`,
   `test/`, `chore/`), never a tool-derived name (`claude/...`, `worktree-...`, `gemini/...`). Rename with
   `git branch -m` before the first push. Commit subjects name the row: `DN11: ...`, `Merge DN11: ...`.
3. **No pull requests.** Push the branch, then the integration pass merges it into `plan` with `--no-ff` in dependency
   order, runs the checks and pushes `plan`. Only the integration pass pushes `plan` and `main`. Never force-push
   either. You may `--force-with-lease` your own feature branch after a rebase.
4. **Seams belong to their rows.** The workspace `Cargo.toml`, `crates/protocol`, `crates/module-api`, the launcher
   bridge spec, `store` migrations, the `clap` tree (`services/host/src/cli.rs`), `.forgejo/` and the generated files
   are shared. A row that needs one more entry in a seam makes the smallest additive edit and lists it in the commit
   body. Never reformat or reorder a seam file.
5. **Generated files are generated.** `RR_UPDATE_GENERATED=1 cargo test -p launcher generated` (run from `rust/`)
   rewrites the bridge TypeScript types (`ui/packages/bridge/src/generated/types.ts`), the isolation hook's command
   list, the permission set and `gen/strings.json`. Never hand-edit them and never hand-merge them: when two branches
   conflict in one, take either side and regenerate.
6. **Ports match Node exactly where a client can see it.** Routes as Express 5 matches them, JSON as `JSON.stringify`
   writes it (field order), status codes, error envelopes. When Node and Rust differ, Rust is the bug unless a
   decision row (DD/RD) says otherwise. Parity and golden tests are the contract: fix the Rust side, and re-record a
   golden only when the Node side changed on purpose.
7. **Security rules that read like overcaution**: the gateway is the only listener off loopback (the TURN relay is the
   one written exception, DD24); host-only routes and headers stay refused at the gateway; the account key (`RRK_...`)
   goes only to the server and certificate it was made for and never crosses a node link or the launcher bridge;
   secrets and keys are never logged; the launcher never injects (RD9); `unsafe`, `unwrap`, `expect`, `todo!` and
   `dbg!` are denied by lint outside tests.
8. **User-facing text goes through the catalogs, both languages, appended at the end.** The UI's catalogs are
   `ui/packages/i18n/catalogs/en.json` and `pt-BR.json` (the `ui/` submodule is the `dainty-lass-ui` repository);
   same keys, same `{placeholders}`, new keys at the END of both files, same order in both. Every new bridge error
   code needs a message key in both catalogs and an entry in `ui/apps/web/src/app/model.ts`'s error table or the UI
   typecheck fails. Never build a sentence by concatenation. Flag pt-BR you are unsure of in the commit body.
9. **Config rules**: a new setting is a `host.toml` field (plus a `hosttoml.rs` key and a `setup` writer), a reader in
   the service's `config.rs`, a round-trip test and a row in `docs/hosting.md`, all in one commit. Secrets go in
   `secrets.env`, never in `host.toml`. Env names use a server prefix (`REFORGED_`, `GATEWAY_`, `CONTENT_`, ...).
10. **Migration versions are global per database.** Two areas that ship the same version number silently lose one set
    (inventory and bounties-store both used `0050`; 77 tests failed until one was renumbered). Taken in
    `rustic-isles/crates/isles-core/migrations/`: 0001 accounts, 0020 auth, 0030 characters, 0050 inventory,
    0055 bounties, 0070 chat edges, 0200-0204 reforged-api, 0500 progression, 0600 parties.
11. **Hands-on work is not yours**: the canary, cutovers, real Epic sign-in and install, running against a real game
    client or server, signing and publishing, anything needing the maintainer's accounts or machines, and anything
    that publishes outside Forgejo. Write the steps down and leave them.
12. **Say what was only tested.** "Tests pass" is not "it works". Nothing here has met a real client.

## 10. Procedures

### 10.1 Integrate a finished branch into `plan`

```bash
git fetch origin
git log --format=%B origin/plan..origin/<branch> | grep -iE 'co-authored|generated with|claude-session'   # must be empty
git worktree add .claude/worktrees/integration origin/plan --detach && cd .claude/worktrees/integration
git merge --no-ff origin/<branch> -m "Merge <ROW>: <what>"
git diff --name-only --diff-filter=U        # conflicts: keep every side's entries; regenerate generated files
git submodule update --init --recursive     # dainty-lass only
# then 10.2; then push ONLY after green:
git push origin HEAD:plan
```

Conflict habits that worked: `Cargo.lock` take either and let cargo regenerate (`cargo metadata` without `--locked`,
then `--locked` must pass); lists of `use` items, enum variants, `declare(...)` calls and catalog keys are additive -
keep both; a submodule gitlink conflict -> `git submodule update` then `git add ui`; when two UI branches conflict in
the catalogs, keep the first's keys then the second's appended, same order in both languages, check both files parse
as JSON with equal key counts. If a merge is not trivial, send the branch back to its author to rebase rather than
hand-merging type files.
