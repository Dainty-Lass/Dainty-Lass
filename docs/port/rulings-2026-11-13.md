# The maintainer's rulings of 2026-11-13

The maintainer took the integration pass's recommendation on every open call listed on 2026-11-13. Each ruling names
the question it settles. A row that implements one cites this page and the ruling's id.

## Version data (port plan item 9, spec-catalog-exporter question 3, lane G)

- **V-1.** Identifier lists and game GUIDs in `version_data.json` are facts about the game and become MIT. This
  extends the 2026-11-05 ruling that identifier lists are facts.
- **V-2.** `rewardCachePlan`, `starterKit.wallet`, `legacyStarter` and the default appearance are Paradox's design
  and stay in a small AGPL design file under `restricted/`.
- **V-3.** `storageTokenSeeds` is derived from AGPL source and is replaced by an MIT list computed from the MIT
  crates' own ids (spec-rustic-isles-1-14-7 §15 item 6).
- **V-4.** `starterKit.defaultWeaponParts` and the existence of every id may be generated on each host from its own
  export, where the MIT exporter makes that possible.

## The MIT runtime (spec-runtime-surface, lane I)

- **RT-1.** Rust: `crates/rustic-isles-runtime` (`cdylib`) with its pure parts in a second crate tested everywhere,
  MinHook through `cc`, and a crate-level `unsafe_code` exception confined to its FFI module.
- **RT-2.** A small hand-written table of the offsets and names the runtime uses is acceptable. It is not a generated
  SDK.
- **RT-3.** The logging-only probes (R19) are not ported. A probe is ported later only for a live bug.
- **RT-4.** A restricted-side agent writes the AGPL seam patch, and the broker design in section 7 is approved.
- **RT-5, RT-6.** The MIT DLL is `rustic-isles-runtime.dll`, loaded before `Rustic-Isles.dll`. Since RD9's
  amendment, the launcher and the Director inject both, in that order, and the loader's ini lists both for Proton.
  The runtime feed, the Guard manifest and the launcher's known-DLL list accept the second DLL during the transition.
- **RT-7.** Answered by the R2 slice spec. That spec finds where the client's chat connects today, and the MIT
  runtime ports the XMPP redirect only if chat needs it.
- **RT-8.** `MYS1`, the `MysticInternalServer.` pipe prefix, `MYSTICPARADOX_GAMESERVER_READY` and the
  `MYSTICPARADOX_` alias are renamed, in one joint cutover with the launcher and the Director (slice R10).
- **RT-9.** No login background until a new image is drawn.
- **RT-10.** The store capture leaves the runtime. The MIT exporter DLL does it, loaded by the Host page (RD9).
- **RT-11.** Patches 0024 and 0029 and the AFK and hub-size number files become `host.toml` settings, passed in the
  environment.
- **RT-12 to RT-18.** Each is settled in the slice spec that owns it, which records the answer.
- **Order.** R0 and R1 are first, with the seam patch. Slices then land two or three at a time, each with its
  play-test.
- **Order, amended the same day.** No slice waits for a play-test. Specs and implementations run as far ahead as
  their dependencies allow, and every slice's play-test is collected for one hands-on pass at the end.
